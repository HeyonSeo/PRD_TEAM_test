# 요구사항 명세: 임대주택 생활 하자 접수·취합 시안

- 근거: [PRD](../prd/lh-defect-intake-prd.md) · 구조: [아키텍처](architecture.md) · 테스트 연결: [추적표](traceability.md)(자동 생성)
- 범위: `mockup/` 시안. 운영 시스템 요구사항은 [범위 밖](#범위-밖-out)에 따로 적었습니다.

## 읽는 법

### 식별자 체계

| 접두어 | 뜻 | 예 |
|---|---|---|
| `G-nn` | 목표. 시안이 이뤄야 하는 결과 | G-01 |
| `FR-SET-nn` | 기능: 현장 단지 설정 | FR-SET-01 |
| `FR-REG-nn` | 기능: 현장 하자 등록 | FR-REG-03 |
| `FR-LIST-nn` | 기능: 현장 접수 목록·상태 변경 | FR-LIST-04 |
| `FR-HQ-nn` | 기능: 본부 취합 화면 | FR-HQ-05 |
| `FR-DEMO-nn` | 기능: 시연 지원 | FR-DEMO-02 |
| `DM-nn` | 데이터·저장소 | DM-02 |
| `NFR-PRIV-nn` · `NFR-UX-nn` · `NFR-REL-nn` · `NFR-ENV-nn` | 비기능: 개인정보 · 사용성 · 안정성 · 환경 | NFR-PRIV-01 |
| `MAN-nn` | 사람이 직접 확인해야 하는 검증 | MAN-01 |
| `OUT-nn` | 이번 범위 밖 | OUT-01 |

### 상태 값

| 상태 | 뜻 | 추적표 검사 |
|---|---|---|
| `충족` | 구현됐고 자동 테스트로 확인됨 | 연결된 테스트가 1개 이상이고 모두 통과해야 함 |
| `미충족` | 요구사항은 정했지만 아직 구현되지 않음 | 빈칸 목록에 표시 |
| `범위 확인` | 구현됐지만 PRD 범위와 부딪혀 결정이 필요함 | 테스트는 돌리되 결정 대기로 표시 |
| `수동` | 자동 테스트로 확인할 수 없음 | MAN 항목으로 사람이 확인 |
| `범위 밖` | 이번에 하지 않음 | 검사 안 함 |

### 테스트 연결 방식

- 테스트는 `mockup/ralph/check.js` 한 파일에 있습니다.
- 어떤 테스트가 어떤 요구사항을 확인하는지는 `mockup/ralph/trace.js`에 적혀 있습니다. 테스트 이름 패턴을 요구사항 ID에 연결합니다.
- `node mockup/ralph/check.js`를 실행하면 테스트 결과 옆에 요구사항 ID가 함께 찍히고, [추적표](traceability.md)가 다시 만들어집니다.
- 아래 경우에는 검사가 실패합니다.
  - 요구사항에 연결되지 않은 테스트가 있을 때
  - `충족` 요구사항에 연결된 테스트가 없을 때
  - 이 문서에 없는 ID를 trace.js가 가리킬 때

## 역할과 접근 권한

시안에는 로그인이 없습니다. 아래 권한은 **화면을 나눠서 흉내 낸 것**이고, 실제로 막지는 않습니다(누구나 단지를 바꾸고 어느 화면이든 열 수 있음). 운영에서는 [OUT-01](#out-01-로그인권한-실제-적용)에서 실제로 적용해야 합니다.

| 역할 | 화면 | 시안에서 할 수 있는 것 | 운영 제안 |
|---|---|---|---|
| 관리사무소 과장 (`R-FIELD`) | `field.html` | 단지 고르기, 등록, 우리 단지 목록 보기, 상태 변경 | 사내 계정에 묶인 **자기 단지만** 등록·조회·상태 변경. 단지 바꾸기 불가 |
| 본부 담당자 (`R-HQ`) | `hq.html` | 12곳 전체 조회, 거르기, 사진 보기 | 담당 단지 전체 **조회만**. 등록·상태 변경 불가 |
| 시연자 (`R-DEMO`) | `index.html` | 시연 데이터 초기화, 화면 열기 | 운영에는 없음 |

| 기능 | R-FIELD | R-HQ | R-DEMO |
|---|---|---|---|
| 접수 등록 (FR-REG) | 자기 단지 | ✕ | ✕ |
| 접수 조회 (FR-LIST, FR-HQ) | 자기 단지 | 담당 단지 전체 | ✕ |
| 상태 변경 (FR-LIST-04) | 자기 단지 | ✕ | ✕ |
| 입주민 연락처 보기 | 마스킹 | 마스킹 | ✕ |
| 데이터 초기화 (FR-DEMO-02) | ✕ | ✕ | 전체 |

## 기능 FR-SET: 현장 단지 설정

**사용자 시나리오**
1. 과장이 처음으로 현장 화면을 연다 → 단지 12곳 버튼이 보인다.
2. 자기 단지를 누른다 → 바로 등록 화면으로 간다. 위쪽에 단지 이름이 보인다.
3. 다음 날 다시 연다 → 단지를 다시 고르지 않고 바로 등록 화면이 나온다.

**접근 권한**: R-FIELD. 시안에서는 "단지 바꾸기"로 아무 단지나 고를 수 있습니다(운영에서는 막아야 함).

### FR-SET-01 첫 실행 때 단지 고르기
- **입력**: 단지 버튼 하나 누르기
- **출력**: 등록 화면으로 이동, 위쪽에 단지 이름 표시
- **성공 조건**: 저장된 단지가 없으면 단지 고르기 화면이 먼저 나오고, 12곳 버튼이 모두 보인다.
- **실패 조건**: 저장된 단지 ID가 데이터에 없으면 단지 고르기 화면으로 돌아간다.
- **경계 조건**: 저장소를 쓸 수 없으면 매번 단지를 다시 고르게 된다(DM-03).
- **완료 기준**: 처음 열면 단지 고르기 화면, 버튼 12개, 누르면 바로 등록 화면이다.
- **관련**: G-01 · PRD 4(로그인 한 번)
- **상태**: 충족

### FR-SET-02 단지 기억과 바꾸기
- **입력**: 다시 열기 / "단지 바꾸기" 누르기
- **출력**: 저장된 단지로 바로 등록 화면이 열림 / 단지 고르기 화면
- **성공 조건**: 한 번 고른 단지는 다시 열어도 유지된다.
- **실패 조건**: 없음(저장 실패 시 FR-SET-01로 돌아감)
- **경계 조건**: 시연 데이터를 초기화하면 기억한 단지도 지워진다(FR-DEMO-02).
- **완료 기준**: 다시 열면 단지 고르기 없이 등록 화면이 나오고, 위쪽에 우리 단지 이름이 보인다.
- **관련**: G-01 · PRD 2(매번 로그인하면 안 씀)
- **상태**: 충족

## 기능 FR-REG: 현장 하자 등록

**사용자 시나리오**
1. 과장이 세대를 방문해 "사진 고르기"를 누르고 사진 여러 장을 한 번에 고른다.
2. 동 버튼 → 호 버튼을 누른다. 입주민 연락처가 자동으로 붙는다(가려서 표시).
3. 한 줄 내용을 쓰거나 "곰팡이" 같은 자주 쓰는 말을 누른다.
4. "등록하기"를 누른다 → "등록 완료 · 38초"가 뜬다. 사무실에서 다시 입력하지 않는다.
5. 다른 세대로 이동해 "한 건 더 등록"을 누른다.

- **대안 흐름**: 사진을 잘못 골랐으면 × 버튼으로 뺀다. 동을 바꾸면 고른 호수가 풀린다.
- **예외 흐름**: 세 가지 중 하나라도 빠지면 등록 버튼이 눌리지 않고 "남은 것: 사진, 동·호수"처럼 알려준다.

**접근 권한**: R-FIELD, 자기 단지에만 등록.

### FR-REG-01 사진 여러 장 한 번에 고르기
- **입력**: 이미지 파일 1장 이상(한 번에 여러 장 선택 가능, 여러 번 나눠 고르면 계속 추가됨)
- **출력**: 미리보기 썸네일, "사진 N장" 표시, 장마다 빼기(×) 버튼
- **성공 조건**: 고른 장수만큼 미리보기가 생긴다.
- **실패 조건**: 이미지가 아닌 파일은 조용히 무시한다. 열 수 없는 이미지도 건너뛴다. 이때 따로 알리지 않는다.
- **경계 조건**
  - 0장이면 등록할 수 없다(FR-REG-06).
  - 장수 상한이 없어서 많이 고르면 저장 용량을 넘을 수 있다(NFR-REL-02).
  - 줄이는 동안에는 "사진을 줄이는 중…"이 뜨고 등록 버튼이 잠긴다.
- **완료 기준**: 사진 2장을 한 번에 고르면 미리보기 2장이 생기고, 등록 뒤 저장소에 2장이 함께 저장된다.
- **관련**: G-01 · PRD 3-1, PRD 2(사진 한 장씩 올리면 안 씀)
- **상태**: 충족

### FR-REG-02 사진 줄여서 저장
- **입력**: FR-REG-01에서 고른 원본 이미지
- **출력**: 긴 변 480px 이하 JPEG dataURL(품질 0.72, 투명 배경은 흰색으로)
- **성공 조건**: 원본 크기와 관계없이 긴 변이 480px 이하가 된다.
- **실패 조건**: 이미지를 열지 못하면 그 장은 빠진다.
- **경계 조건**: 480px보다 작은 이미지는 키우지 않는다.
- **완료 기준**: 저장된 사진이 `data:image/jpeg`이고 긴 변이 480px 이하다.
- **관련**: G-01 · 저장소 용량 안에서 시연을 끝까지 돌리기 위함
- **상태**: 충족

### FR-REG-03 동 → 호 버튼 고르기
- **입력**: 동 버튼 1번, 호 버튼 1번(타이핑 없음)
- **출력**: 선택한 버튼 강조, 호 목록은 층별 격자
- **성공 조건**: 동을 누르면 그 동의 호 버튼이 나온다.
- **실패 조건**: 없음
- **경계 조건**: 동을 먼저 누르지 않으면 "동을 먼저 누르면 호수가 나옵니다"가 뜬다. 동을 바꾸면 고른 호가 풀린다.
- **완료 기준**: 동을 누르면 호 버튼 목록이 나온다.
- **관련**: G-01 · PRD 3-1(동·호수는 목록에서 선택)
- **상태**: 충족

### FR-REG-04 입주민 연락처 자동으로 붙이기
- **입력**: FR-REG-03의 동·호수(따로 입력 칸 없음)
- **출력**: "101동 202호 · 입주민 박○○ · 010-****-3200 · 연락처는 자동으로 붙습니다"
- **성공 조건**: 동·호수를 고르는 즉시 마스킹된 이름·연락처가 보인다.
- **실패 조건**: 세대 정보가 없으면 "입주민 정보 없음"이 뜨고, 등록은 계속할 수 있다.
- **경계 조건**: 연락처는 접수에 저장하지 않고 볼 때마다 조회한다(DM-02).
- **완료 기준**: 입력 칸은 사진·한 줄뿐이고 연락처 입력 칸이 없다. 동·호수를 고르면 마스킹된 연락처가 자동으로 보인다.
- **관련**: G-01, G-05 · PRD 4(연락처는 업체 방문 일정에 필요)
- **상태**: 충족

### FR-REG-05 한 줄 내용
- **입력**: 글자 1~60자, 또는 자주 쓰는 말 버튼(물이 샘, 곰팡이, 방충망 찢어짐, 문이 안 닫힘, 전등 안 켜짐, 보일러 고장)
- **출력**: 입력 칸에 내용, 자주 쓰는 말을 여러 번 누르면 쉼표로 이어 붙음
- **성공 조건**: 앞뒤 공백을 뺀 내용이 1자 이상이다.
- **실패 조건**: 공백만 있으면 내용이 없는 것으로 본다.
- **경계 조건**: 60자를 넘으면 더 입력되지 않는다.
- **완료 기준**: FR-REG-06·07 테스트에서 한 줄 내용이 그대로 저장된다.
- **관련**: G-01 · PRD 3-1(한 줄)
- **상태**: 충족

### FR-REG-06 등록 가능 조건과 안내
- **입력**: 사진·동·호수·한 줄의 현재 상태
- **출력**: 등록 버튼 사용 가능 여부, "남은 것: …" 또는 "준비됐습니다" 안내
- **성공 조건**: 사진 1장 이상, 동·호수, 한 줄이 모두 있고 사진 처리가 끝났을 때만 버튼이 눌린다.
- **실패 조건**: 하나라도 빠지면 버튼이 잠기고 빠진 항목 이름을 보여준다.
- **경계 조건**: 사진을 줄이는 중이면 셋 다 채워져도 잠긴다.
- **완료 기준**: 처음에는 버튼이 잠겨 있고, 세 가지를 채우면 열린다.
- **관련**: G-01 · PRD 2(입력 칸이 엑셀보다 많으면 안 씀)
- **상태**: 충족

### FR-REG-07 접수 저장
- **입력**: 단지·동·호수·한 줄·사진
- **출력**: 새 접수 1건(`status=접수`, 접수 시각, 상태 시각, 이력 1개), 목록 맨 위
- **성공 조건**: 저장소에 1건이 늘고 내용이 입력과 같다.
- **실패 조건**: 저장소 쓰기가 실패해도 지금은 알리지 않는다(NFR-REL-02 미충족).
- **경계 조건**: 같은 세대에 여러 건을 등록할 수 있다(중복 막지 않음).
- **완료 기준**: 등록하면 store에 1건이 늘고 단지·동·호수·내용·사진 2장이 맞게 저장된다.
- **관련**: G-01, G-02 · PRD 3 차별점(사무실 재입력 없음)
- **상태**: 충족

### FR-REG-08 걸린 시간과 완료 화면
- **입력**: 등록 화면을 연 시각, 등록한 시각
- **출력**: "등록 완료 · 00초"(60초 이상이면 "1분 05초"), 등록 요약, "한 건 더 등록"·"접수 목록 보기" 버튼
- **성공 조건**: 등록 화면을 연 순간부터 잰 초가 보인다.
- **실패 조건**: 없음
- **경계 조건**: 사진을 고르는 시간도 포함한다. "한 건 더 등록"을 누르면 다시 0부터 잰다.

## 기능 FR-LIST: 현장 접수 목록과 상태 변경

**사용자 시나리오**
1. 입주민이 "202호인데 접수한 거 어떻게 됐어요?"라고 전화한다.
2. 과장이 "접수 목록"을 누르고 `101 202`를 친다 → 그 세대 건만 나온다.
3. 상태(업체 배정, 9일째)를 보고 바로 답한다.
4. 업체가 다녀갔으면 "보수 완료로 바꾸기" 버튼을 한 번 누른다 → 본부 화면에도 바로 반영된다.

**접근 권한**: R-FIELD, 자기 단지 건만 보고 바꾼다.

### FR-LIST-01 우리 단지 접수 목록
- **입력**: "접수 목록" 탭
- **출력**: 자기 단지 접수만 최근 순으로. 건마다 동·호수, 내용, 사진, 마스킹된 입주민 정보, 상태, 경과 일수
- **성공 조건**: 다른 단지 건이 섞이지 않는다.
- **실패 조건**: 없음
- **경계 조건**: 접수가 0건이면 "해당하는 접수가 없습니다"가 나온다.
- **완료 기준**: 접수 목록 탭이 있고, 누르면 우리 단지 건만 최근 순으로 보인다.
- **관련**: G-03 · PRD 3-3
- **상태**: 충족

### FR-LIST-02 동·호수로 찾기
- **입력**: 숫자 검색어. `101 1203`, `101동 1203호`, `1011203`, `1203`
- **출력**: 조건에 맞는 건만 표시. 없으면 안내 문구
- **성공 조건**
  - 숫자 두 덩어리: 앞은 동, 뒤는 호의 앞부분과 맞춘다.
  - 6자리 이상 한 덩어리: 동+호를 붙인 값 안에서 찾는다.
  - 한 덩어리: 동 또는 호의 앞부분과 맞춘다.
- **실패 조건**: 맞는 건이 없으면 "이 동·호수로 들어온 접수가 없습니다"가 나온다.
- **경계 조건**: 숫자가 없으면 전체가 나온다. `1`처럼 짧으면 넓게 걸린다. 상태를 바꿔도 검색어는 유지된다.
- **완료 기준**: 세 가지 입력 형식이 모두 그 세대 건을 찾고, 없는 동·호수면 안내 문구가 나온다.
- **관련**: G-03 · PRD 2(재문의 전화)
- **상태**: 충족

### FR-LIST-03 상태로 거르기
- **입력**: 전체 / 접수 / 업체 배정 / 보수 완료 버튼
- **출력**: 그 상태 건만 표시
- **성공 조건**: 고른 상태 건만 보인다. 검색과 함께 적용된다.
- **실패 조건**: 없음
- **경계 조건**: 결과가 0건이면 "해당하는 접수가 없습니다"가 나온다.
- **완료 기준**: 상태 버튼으로 걸러진다.
- **관련**: G-03
- **상태**: 충족

### FR-LIST-04 상태 한 단계 넘기기
- **입력**: 건마다 "업체 배정으로 바꾸기" 또는 "보수 완료로 바꾸기" 버튼 한 번
- **출력**: 접수 → 업체 배정 → 보수 완료, 이력 추가, 화면 배지 변경, 본부 반영(FR-HQ-05)
- **성공 조건**: 한 번 누르면 다음 단계로 넘어가고 저장소에 남는다.
- **실패 조건**: 정해진 세 상태 외의 값은 저장소가 거부한다(DM-02).
- **경계 조건**: 보수 완료 건에는 버튼이 없다. 되돌리기 기능은 없다. 새로고침해도 유지된다.
- **완료 기준**: 업체 배정 → 보수 완료가 store와 화면에 반영되고, 이력이 순서대로 남고, 보수 완료 건에는 버튼이 없다.
- **관련**: G-03 · PRD 3-3
- **상태**: 충족

### FR-LIST-05 경과 일수
- **입력**: 접수 시각, 상태 시각, 현재 시각
- **출력**: "오늘" 또는 "N일째"(상태가 바뀐 날 기준)
- **성공 조건**: 경과 일수가 상태 바뀐 날을 기준으로 맞게 표시된다.
- **실패 조건**: 없음
- **경계 조건**: 0일이면 "오늘"로 표시한다.
- **완료 기준**: 상태와 경과 일수가 표시되고, 상태 바뀐 날 기준이다.
- **관련**: G-03
- **상태**: 충족

### FR-LIST-06 7일 넘게 멈춘 건 경고 (현장)
- **입력**: 보수 완료 전이면서 상태 바뀐 지 7일 이상
- **출력**: "⚠ 멈춤" 경고
- **결정 필요**: PRD는 "처리 속도는 범위 밖"이라고 정했습니다. 이 경고는 처리 속도를 재는 기능이라 PRD와 부딪힙니다. 또 과장에게 감시 도구로 느껴져 채택 목표(PRD 5 핵심 지표)를 해칠 수 있습니다. 경고를 빼고 경과 일수(FR-LIST-05)만 남길지 결정해야 합니다.
- **경계 조건**: 기준 7일이 `field.html`과 `hq.html`에 따로 들어 있습니다.
- **완료 기준**: 7일 넘게 멈춘 진행 중 건에 경고가 뜬다.
- **관련**: PRD 1 배경(범위 밖)
- **상태**: 범위 확인

## 기능 FR-HQ: 본부 취합 화면

**사용자 시나리오**
1. 본부 담당자가 아침에 본부 화면을 연다 → "이번 주 취합: 자동 완료"와 단지 12곳 카드가 보인다.
2. 표에서 12곳 접수를 같은 양식으로 훑는다. 필요하면 단지·상태로 거르고 사진을 크게 본다.
3. 화면을 열어둔 동안 현장에서 새 건이 들어오면, 새로고침 없이 맨 위에 "방금 들어옴"으로 뜬다.
4. 엑셀을 받아 맞추는 일 없이 30분 안에 확인을 끝낸다.

**접근 권한**: R-HQ, 조회만 할 수 있음. 등록·상태 변경 버튼이 없다.

### FR-HQ-01 단지 12곳 카드
- **입력**: 저장소 전체 접수
- **출력**: 단지마다 접수·진행 중·완료 건수, 위쪽 합계(전체·진행 중·보수 완료)
- **성공 조건**: 카드 건수가 저장소와 맞는다.
- **실패 조건**: 없음
- **경계 조건**: 접수가 0건인 단지도 카드는 나온다.
- **완료 기준**: 카드 12개이고, 카드마다 건수가 맞다.
- **관련**: G-02 · PRD 3-2
- **상태**: 충족

### FR-HQ-02 한 양식으로 모인 표
- **입력**: 저장소 전체 접수
- **출력**: 단지·동·호수·내용·사진·상태·접수일·경과일 8열 표, 최근 순
- **성공 조건**: 12곳 접수가 모두 같은 열 구성으로 들어가고, 행 내용이 저장소와 같다.
- **실패 조건**: 없음
- **경계 조건**: 걸러서 0건이면 "조건에 맞는 접수가 없습니다"가 나온다.
- **완료 기준**: 12곳 전체가 표에 모이고, 8열 양식이며, 행 내용이 store와 같다.
- **관련**: G-02 · PRD 1 문제(양식이 단지마다 다름)
- **상태**: 충족

### FR-HQ-03 거르기
- **입력**: 단지 선택 상자, 상태 버튼, 단지 카드 누르기(한 번 더 누르면 풀림)
- **출력**: 조건에 맞는 행만 표시
- **성공 조건**: 단지·상태 조건이 함께 적용된다.
- **실패 조건**: 없음
- **경계 조건**: 같은 카드를 다시 누르면 전체로 돌아간다.
- **완료 기준**: 단지로, 상태로, 카드로 거르기가 되고, 카드를 다시 누르면 전체가 나온다.
- **관련**: G-02
- **상태**: 충족

### FR-HQ-04 사진 크게 보기
- **입력**: 표의 사진 썸네일 누르기
- **출력**: 폭 300px 이상으로 크게 보기, 닫기 버튼
- **성공 조건**: 방금 등록된 사진도 크게 보인다.
- **실패 조건**: 없음
- **경계 조건**: 사진은 480px로 줄여 저장했으므로 그보다 크게 보이지 않는다.
- **완료 기준**: 사진을 누르면 300px 이상으로 열리고, 닫기를 누르면 닫힌다.
- **관련**: G-02 · PRD 1 문제(사진이 따로 옴)
- **상태**: 충족

### FR-HQ-05 새로고침 없이 반영
- **입력**: 같은 브라우저의 다른 탭에서 저장소가 바뀜(등록, 상태 변경, 초기화)
- **출력**: 표·카드 다시 그리기, 새 건은 맨 위에 8초 동안 강조, "새 접수 1건: …" 알림
- **성공 조건**: 현장 등록과 상태 변경이 본부 표·카드에 바로 나타난다.
- **실패 조건**: 다른 브라우저나 다른 기기에서 바꾼 것은 반영되지 않는다(서버 없음, OUT-02).
- **경계 조건**: 한 번에 6건 이상 바뀌면(초기화 등) 강조하지 않는다.
- **완료 기준**: 현장에서 등록한 건이 열린 본부 탭에 새로고침 없이 맨 위에 강조되어 나타나고, 건수와 상태 변경도 바로 반영된다.
- **관련**: G-02 · PRD 1 기대 변화(취합 주 1일 → 30분)
- **상태**: 충족

### FR-HQ-06 이번 주 취합 요약
- **입력**: 이번 주 월요일 이후 접수
- **출력**: "이번 주 취합: 자동 완료 · 단지 12곳 접수가 등록 즉시 모였습니다. 이번 주 새 접수 N건(M개 단지)…"
- **성공 조건**: 위쪽 한 줄에 표시된다.
- **실패 조건**: 없음
- **경계 조건**: 이번 주 접수가 0건이어도 문구는 나온다.
- **완료 기준**: "이번 주 취합: 자동 완료" 요약이 보인다.
- **관련**: G-02 · PRD 1 기대 변화
- **상태**: 충족

### FR-HQ-07 7일 넘게 멈춘 건 경고 (본부)
- **입력**: FR-LIST-06과 같은 기준
- **출력**: 단지 카드 빨간 경고, 위쪽 "7일 넘게 멈춤" 합계, 상태 필터 "7일 넘게 멈춤", 표의 "⚠ N일 멈춤"
- **결정 필요**: FR-LIST-06과 같습니다. 더해서, 지금 시드 데이터로는 진행 중 21건 중 15건이 경고로 뜨고 카드 12개 중 10개가 빨갛게 보입니다. 시연 메시지가 "자동 취합"보다 "현장 처리 지연"으로 읽힐 위험이 있습니다.
- **완료 기준**: 멈춘 건이 있는 카드에만 경고가 뜬다.
- **관련**: PRD 1 배경(범위 밖), G-04 위험
- **상태**: 범위 확인

  - 입주민 이름·연락처는 접수에 저장하지 않는다.
- **실패 조건**: 정해진 세 상태 외의 값으로 바꾸면 거부하고 `null`을 돌려준다.
- **완료 기준**: add 후 1건이 늘어 맨 위에 오고, setStatus가 반영되고, 잘못된 상태는 거부되고, reset 후 시드 건수로 돌아간다.
- **관련**: 아키텍처 5(운영 전환 교체 지점)
- **상태**: 충족

### DM-03 저장소를 쓸 수 없을 때
- **내용**: localStorage가 막혀 있으면(사생활 보호 모드 등) 메모리에 대신 저장하고, 화면이 에러 없이 시드를 보여준다.
- **경계 조건**: 이 경우 새로고침하면 데이터가 사라지고, 탭끼리 반영되지 않는다.
- **완료 기준**: localStorage를 막은 상태에서도 에러 없이 시드가 보인다.
- **상태**: 충족

## 수동 검증 MAN

자동 테스트는 화면이 정해진 대로 움직이는지만 확인합니다. 목표가 실제로 이뤄졌는지는 사람이 확인해야 합니다.

### MAN-01 실제 과장이 1분 안에 등록
- **방법**: 관리사무소 과장 1~2명에게 폰으로 실제 사진을 찍어 등록하게 하고, 완료 화면의 초를 기록한다. 설명 없이 처음 써보는 상태에서 잰다.
- **완료 기준**: 처음 쓰는 사람이 60초 안에 끝내고, "엑셀보다 낫다"고 말한다.
- **관련**: G-01
- **상태**: 수동

### MAN-02 본부 담당자가 한 화면으로 확인
- **방법**: 본부 담당자가 본부 화면만 보고 이번 주 접수를 확인하는 데 걸린 시간을 잰다.
- **완료 기준**: 30분 안에 끝나고, 엑셀이나 메일을 따로 열지 않는다.
- **관련**: G-02
- **상태**: 수동

### MAN-03 3분 시연 리허설
- **방법**: README 대본대로 다른 사람 앞에서 리허설하고 시간을 잰다. 화면을 보고 받은 첫 인상을 한 줄로 받아 적는다.
- **완료 기준**: 3분 안에 끝나고, 첫 인상이 "취합이 자동으로 된다" 쪽이다("현장 처리가 밀렸다" 쪽이면 FR-HQ-07 결정을 다시 본다).
- **관련**: G-04
- **상태**: 수동
