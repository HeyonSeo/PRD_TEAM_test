# 수동 검증 키트

자동 테스트(`node mockup/ralph/check.js`)는 화면이 명세대로 움직이는지만 확인합니다. 아래 세 가지는 **실제 사람이 써 봐야** 알 수 있어서, 같은 방식으로 재고 같은 양식에 남기도록 이 키트를 만들었습니다.

| ID | 무엇을 확인하나 | 누가 | 걸리는 시간 | 양식 |
|---|---|---|---|---|
| MAN-02 | 본부 담당자가 본부 화면만으로 이번 주 확인을 30분 안에 끝내는가 | 본부 담당자(본인) | 30분 이내 | [man-02-hq-review.md](man-02-hq-review.md) |
| MAN-01 | 처음 쓰는 과장이 폰으로 60초 안에 등록하는가 | 관리사무소 과장 1~2명 + 진행자 | 1인당 15분 | [man-01-field-registration.md](man-01-field-registration.md) |
| MAN-03 | 3분 안에 시연을 끝내고, 보는 사람이 "취합이 자동"으로 이해하는가 | 시연자(본인) + 청중 1명 | 15분 | [man-03-demo-rehearsal.md](man-03-demo-rehearsal.md) |

요구사항 정의는 [requirements.md의 수동 검증 MAN](../requirements.md#수동-검증-man) 절에 있습니다.

## 진행 순서

1. **MAN-02**를 먼저 혼자 해 봅니다. 시안 화면에 익숙해지고, 본부 쪽에서 막히는 곳을 미리 찾습니다.
2. **MAN-01**을 과장님과 진행합니다. 가장 중요한 검증입니다. 과장님이 이 도구를 안 쓰면 다시 엑셀로 돌아가기 때문입니다(PRD 2).
3. **MAN-03** 리허설은 마지막에 합니다. MAN-01·02에서 나온 질문과 막힌 곳을 대본에 반영한 뒤 진행합니다.

한 가지가 통과하지 못하면 다음으로 넘어가기 전에 원인을 기록합니다. 화면 수정이 필요하면 GitHub 이슈를 만들고, 고친 뒤 그 검증만 다시 합니다.

## 준비

### 공통
- 크롬이나 엣지가 있는 PC
- `mockup/` 폴더. 여는 방법은 [mockup/README.md](../../mockup/README.md)에 있습니다.
- 매 검증 시작 전에 `index.html`의 **시연 데이터 초기화**를 누릅니다. 이전 기록이 남아 있으면 결과가 섞입니다.
- 초를 잴 수 있는 시계(폰 스톱워치)

### 현장 화면을 폰으로 여는 방법 (MAN-01)
시안에는 서버가 없어서, 폰에서 열려면 PC를 잠깐 서버로 씁니다.

1. PC의 `mockup` 폴더에서 아래 명령을 실행합니다.
   ```bash
   python3 -m http.server 8000
   ```
2. PC와 폰을 **같은 와이파이**에 연결하고, 폰 브라우저에서 `http://<PC의 IP 주소>:8000/field.html`을 엽니다.
3. 사내망에서 PC 간 접속이 막혀 있거나 보안 규정상 허용되지 않으면 이 방법은 쓰지 않습니다. 그때는 PC 크롬의 기기 모드(F12 → 폰 모양 아이콘)로 진행하고, 양식의 "사용 기기"에 그렇게 적습니다. 실제 폰보다 결과의 무게가 가볍다는 점도 함께 적어 둡니다.

폰과 PC는 브라우저가 달라서 데이터가 서로 오가지 않습니다(시안의 한계). MAN-01은 현장 화면만 보면 되므로 문제없습니다.

### 개인정보
- 화면의 입주민 정보는 모두 가짜입니다.
- MAN-01에서 사진을 찍을 때는 **관리사무소 벽, 복도처럼 사람과 세대 내부가 나오지 않는 곳**을 찍습니다. 사진은 그 폰 브라우저 안에만 저장되고 외부로 나가지 않습니다.
- 검증이 끝나면 그 폰에서도 `index.html`을 열어 **시연 데이터 초기화**를 눌러 지웁니다.
- 기록지에는 참가자 실명 대신 "A 과장(○○단지)"처럼 적습니다.

## 기록 남기기

1. 양식 파일을 복사해 `docs/validation/records/`에 저장합니다. 이름은 `날짜-ID-참가자.md`로 짓습니다.
   예: `records/2026-11-12-man-01-A과장.md`
2. 양식의 빈칸을 채웁니다. **통과 여부는 양식의 기준표대로만** 정합니다. "거의 됐다"는 통과가 아닙니다.
3. 결과를 [requirements.md](../requirements.md)의 해당 MAN 항목에 반영합니다.
   - **통과**: `- **상태**: 수동` → `- **상태**: 수동 통과`로 바꾸고, 그 위에 `- **기록**: [날짜](validation/records/파일명.md)` 줄을 넣습니다.
   - **통과 못 함**: 상태는 `수동`으로 둡니다. `- **기록**:` 줄에 결과와 만든 이슈 번호를 적습니다.
4. `node mockup/ralph/check.js`를 실행하면 [추적표](../traceability.md)가 다시 만들어집니다. `수동 통과` 항목은 ✅로 바뀌고 "남은 일"에서 빠집니다.
5. 세 가지가 모두 `수동 통과`가 되면 [#6](https://github.com/HeyonSeo/PRD_TEAM_test/issues/6)을 닫고 부서장 시연 일정을 잡습니다.

## 진행자 공통 원칙

- **설명하지 않습니다.** "이 화면으로 하자 한 건을 등록해 주세요"까지만 말합니다. 참가자가 물어보면 "평소 하시는 대로 해 보세요"라고 답합니다. 진행자가 도와준 순간이 있으면 양식에 적습니다.
- **막힌 곳을 적습니다.** 몇 초 넘게 멈추거나, 잘못 누르거나, 물어본 곳이 다음 개선의 단서입니다.
- **참가자 말을 그대로 적습니다.** "편하네요"와 "이건 좀…"을 요약하지 말고 들은 대로 받아 적습니다.
