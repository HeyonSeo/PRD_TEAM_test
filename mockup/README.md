# 임대주택 생활 하자 접수·취합 시안

부서장·전산 부서 앞에서 3분 동안 두 장면을 보여 주기 위한 화면 시안입니다.

1. 관리사무소 과장이 현장에서 폰으로 하자 한 건을 1분 안에 등록하는 장면
2. 그 건이 본부 화면에 단지 12곳 접수와 함께 같은 양식으로 바로 모이는 장면

모든 데이터는 가짜입니다(가상의 단지 12곳, 가짜 입주민, 가짜 접수 40건). 저장은 이 컴퓨터 브라우저 안(localStorage)에만 하고, 외부로는 아무것도 보내지 않습니다. 외부 글꼴·라이브러리도 쓰지 않습니다.

## 여는 방법

설치할 것은 없습니다. 크롬 또는 엣지 하나만 있으면 됩니다.

- 가장 간단한 방법: `mockup/index.html` 파일을 크롬으로 엽니다.
- 파일로 열었을 때 화면 사이 반영이 안 되면, `mockup` 폴더에서 아래 명령으로 띄운 뒤 `http://localhost:8000/index.html`을 엽니다.
  ```
  python3 -m http.server 8000
  ```
- 현장 화면은 폰 폭(375px) 기준입니다. PC에서 보여 줄 때는 크롬 개발자 도구(F12)의 기기 모드로 폰 크기를 맞추거나, 창을 좁게 줄여 옆에 둡니다.
- 같은 브라우저의 두 탭(현장·본부)끼리 데이터가 바로 오갑니다. 다른 브라우저나 다른 기기끼리는 오가지 않습니다(서버가 없는 시안이기 때문).

| 파일 | 화면 |
|---|---|
| `index.html` | 시연 시작 화면(문제 한 줄, 시연 순서, 지금 방식 비교, 데이터 초기화) |
| `field.html` | 현장 화면(폰): 단지 고르기, 새로 등록, 접수 목록 |
| `hq.html` | 본부 화면(PC): 단지 12곳 카드, 한 양식으로 모인 접수 표 |

## 시연 전 준비 (1분)

1. `index.html`을 열고 **시연 데이터 초기화**를 누릅니다. 접수 40건 상태로 돌아가고, 현장 화면의 "우리 단지" 기억도 지워집니다.
2. **본부 화면 열기**를 눌러 본부 탭을 띄워 둡니다(PC 폭).
3. **현장 화면 열기**를 눌러 현장 탭을 띄우고 폰 폭으로 맞춥니다.
4. 등록에 쓸 사진 2~3장을 바탕화면 등 찾기 쉬운 곳에 둡니다(아무 사진이나 됩니다).

## 3분 시연 대본

**0:00 – 0:30 문제 (시작 화면)**
> "지금은 단지 12곳 하자 접수가 엑셀·카톡·메일로 따로 와서, 본부에서 맞추는 데만 주 1일이 듭니다. 이 시안은 현장에서 한 번 등록하면 본부까지 바로 모이는 모습을 보여 드립니다."

아래 비교표(주 1일 → 매일 아침 30분, 재입력 없음, 카톡 사진 이동 없음)를 손으로 짚고 넘어갑니다.

**0:30 – 1:30 장면 1: 현장에서 1분 등록 (현장 화면, 폰 폭)**
1. 단지 목록에서 "은빛마을 3단지"를 누릅니다. "단지는 처음 한 번만 고릅니다. 매번 로그인하지 않습니다."
2. **사진 고르기**를 눌러 사진 여러 장을 한 번에 고릅니다. "한 장씩 올리지 않습니다."
3. 동 버튼 → 호 버튼을 누릅니다. "타이핑이 없습니다. 입주민 연락처는 자동으로 붙고, 화면에는 가려서 보입니다."
4. 자주 쓰는 말(예: "곰팡이")을 누르거나 한 줄을 적고 **등록하기**를 누릅니다.
5. 완료 화면의 "등록 완료 · 00초"를 보여 줍니다. "입력 칸은 사진, 동·호수, 한 줄 세 가지뿐입니다. 사무실에 와서 다시 칠 필요가 없습니다."

**1:30 – 2:20 장면 2: 본부에 바로 모임 (본부 화면, PC 폭)**
1. 본부 탭으로 넘어갑니다. 새로고침 없이 표 맨 위에 방금 건이 "방금 들어옴"으로 강조돼 있습니다.
2. "12곳 접수가 모두 같은 양식(단지, 동·호수, 내용, 사진, 상태, 접수일, 경과일)으로 모여 있습니다. 이번 주 취합은 자동으로 끝났습니다."
3. 사진 썸네일을 눌러 크게 봅니다. "카톡으로 옮길 필요가 없습니다."
4. 단지 카드 하나를 누르면 그 단지 건만 보입니다. "단지별로 몇 건이 들어와 어디까지 갔는지 한눈에 봅니다." 처리 속도를 물으면: "건마다 경과 일수가 보이고, 처리 속도 관리는 업체 계약과 묶여 있어 시범 뒤 별도로 논의하겠습니다."

**2:20 – 3:00 처리 상태 (현장 → 본부)**
1. 현장 탭에서 **접수 목록 보기** → 동·호수로 찾기에 방금 동·호수를 넣습니다. "입주민이 전화하면 이렇게 바로 찾아 답합니다."
2. **업체 배정으로 바꾸기**를 누릅니다.
3. 본부 탭으로 돌아가면 상태가 이미 "업체 배정"으로 바뀌어 있습니다.
4. 마무리: "내년 상반기 단지 2~3곳에서 시범으로 써 보고, 엑셀·메일로 따로 오는 건이 한 달 1~2건 이하인지 보겠습니다."

## PRD 기능과 화면 대응표

| PRD 기능 | 화면 | 어디서 보여 주나 |
|---|---|---|
| 현장 등록(사진 여러 장 한 번에, 동·호수 목록 선택, 한 줄, 1분 안에) | `field.html` 새로 등록 | 사진 고르기 → 동·호 버튼 → 한 줄 → 등록, 완료 화면의 경과 초 |
| 로그인은 한 번만 | `field.html` 단지 고르기 | 처음 한 번 고르면 다음부터 바로 등록 화면 |
| 본부 자동 취합(12곳 같은 양식) | `hq.html` | 단지 12곳 카드, 한 양식 표, "이번 주 취합: 자동 완료", 새 건 실시간 강조 |
| 처리 상태 표시(접수 → 업체 배정 → 보수 완료) | `field.html` 접수 목록, `hq.html` 표 | 버튼 한 번에 다음 상태, 경과 일수 |
| 입주민 문의에 바로 답하기 | `field.html` 접수 목록 | 동·호수로 찾기 |
| 개인정보(외부 전송 없음, 연락처 보호) | 모든 화면 | 맨 위 "가짜 데이터 · 외부로 전송되지 않음", 이름·연락처 가림(김○○, 010-****-1234) |
| 기대 변화(주 1일 → 매일 30분 등) | `index.html` | 지금 방식과 이 도구 비교표 |

## 시안에서 일부러 뺀 것

설득용 시안이라 두 장면에 필요 없는 것은 넣지 않았습니다. 실제 운영 때 전산 부서와 정할 부분입니다.

- **로그인·권한**: 단지 고르기로 대신했습니다. 실제로는 사내 계정으로 한 번 로그인하고 기억하는 방식이 필요합니다.
- **서버·데이터베이스**: 데이터는 이 브라우저 안에만 있습니다. 현장 폰과 본부 PC가 실제로 이어지려면 서버가 필요합니다.
- **사내망 연동·정보보안 심의**: 사내망 안에서 돌리는 방식과 심의 절차는 아직 정하지 않았습니다. 외부 메일·외부 클라우드·개인 카톡은 쓰지 않는다는 원칙만 화면에 반영했습니다.
- **입주민 직접 조회·문자 알림, 엑셀 내려받기**: PRD에서 "추후"로 둔 기능이라 넣지 않았습니다.
- **업체 배정 상세(업체 이름, 방문 일정)**: 처리 속도는 업체 계약·예산 문제라 범위 밖입니다.
