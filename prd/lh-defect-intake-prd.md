# PRD: 임대주택 생활 하자 현장 접수·취합 도구 (설득용 시안)

> PRD 심층 인터뷰(코어 페이스)로 작성했습니다. 인터뷰이는 LH 지역본부 주거복지 부서 직원 **가상 페르소나**(30대 후반 차장급, 공공임대 입주민 관리·민원 7년차, 비개발자)입니다. 실존 인물이 아닙니다.

## 1. 프로젝트 개요
- **해결하려는 문제**: 단지 12곳의 하자 접수가 단지마다 다른 엑셀 양식과 따로 오는 사진으로 메일에 흩어져 있어 한곳에 모이지 않는다. 그래서 입주민도 진행 상황을 알 수 없다.
- **배경**: 본부 담당자는 취합에만 주 1일을 쓰고, "어떻게 됐냐"는 재문의 전화가 하루 3~4통 온다. 관리사무소 직원도 엑셀 정리와 사진 이동에 시간을 쓴다. 처리 속도 자체는 업체 계약·예산 문제라 범위 밖이다.
- **기대 변화**: 취합 주 1일 → 매일 아침 30분 확인. 재문의 전화 절반 이하. 아낀 시간으로 단지 현장 방문을 분기 1회보다 늘린다. 카톡으로 사진을 옮기는 개인정보 관행도 정리된다.

## 2. 사용자 분석
- **주 사용자**: 단지 관리사무소 과장(50대 초반, 12개 단지에 1명씩 총 12명). 혼자 하자·민원·시설을 맡고, PC는 엑셀·메일 정도, 사진은 폰으로 찍어 카톡으로 PC에 옮긴다.
  - 입주민은 어르신 비율이 높아 주로 전화·방문으로 접수하므로 직접 쓰는 사용자가 아니다.
  - 본부 담당자는 결과를 받아보는 사용자다.
- **사용 맥락**: 전화 접수 → 메모지에 동·호수·내용 → 오전·오후에 여러 세대를 묶어 돌며 사진 → 사무실에서 엑셀에 몰아 입력 → 금요일에 본부로 메일.
- **현재 해결 방식과 한계**: 엑셀 + 카톡 사진 + 메일. 양식이 단지마다 다르고 사진이 따로 놀아 본부에서 다시 맞춰야 한다.
- **채택 조건(외면 조건)**: 입력 칸이 엑셀보다 많거나, 사진을 한 장씩 올려야 하거나, 매번 로그인해야 하면 "그냥 엑셀로 할게요"가 된다.

## 3. 기능 요구사항
핵심 기능 (우선순위 순)
1. **현장 등록**: 폰에서 사진 여러 장을 한 번에 고르고, 동·호수는 목록에서 선택하고, 내용은 한 줄. 1분 안에 끝난다.
2. **본부 자동 취합**: 단지 12곳의 접수가 같은 양식으로 본부 화면 한 곳에 모인다.
3. **처리 상태 표시**: 접수 → 업체 배정 → 보수 완료. 입주민이 문의하면 과장이 바로 답할 수 있다.

추후: 입주민 직접 조회·문자 알림, 엑셀 내려받기(윗선 보고용)

- **차별점**: 지금은 현장 메모 → 사무실 재입력 → 사진 따로 → 메일 순서지만, 이 도구는 현장에서 한 번 등록하면 본부까지 끝난다. "사무실 와서 다시 안 쳐도 된다"가 핵심이다. 기존 하자 전산은 준공 직후 하자담보 위주라 입주 후 생활 하자 접수에는 쓰이지 않는다.

## 4. 비기능 요구사항
- **사용 환경**: 관리사무소 과장은 현장에서 폰(앱 설치 없이 인터넷 주소로 열림, 로그인은 한 번만), 본부 담당자는 사무실 PC.
- **데이터 민감도**: 동·호수, 입주민 이름·연락처(업체 방문 일정용), 세대 내부 사진(생활 모습 포함). 수급자 여부 같은 정보는 넣지 않는다. 외부 메일·외부 클라우드·개인 카톡은 원칙적으로 사용할 수 없다.
  - 실제 운영: 사내망 + 정보보안 심의 필요
  - 시안 단계: **가짜 데이터만** 사용
- **제약**: 본인이 바이브코딩으로 화면·흐름 시안 제작 → 부서장 승인 → 전산 부서(또는 협력 업체)가 운영. 예산 없음. 올해 안에 시안, 내년 상반기 단지 2~3곳 시범. 정보보안 심의 절차는 아직 모른다.

## 5. 성공 지표
- **성공 모습**
  - 올해 말: 부서장이 "내년 상반기에 2~3곳 시범 해봐라"고 승인한다. 전산 부서가 "검토해보자"고 하면 절반은 성공이다.
  - 시범 6개월 후: 시범 단지 과장들이 엑셀 없이 이 도구로만 접수한다.
- **핵심 지표**: 시범 단지별 월간 하자 접수 중 이 도구로 들어온 비율. 엑셀·메일로 따로 온 건이 **한 달에 1~2건 이하**면 성공으로 본다. 월말에 확인한다.
- **따라오는 지표**: 본부 취합 시간 주 1일 → 하루 30분, 재문의 전화 하루 3~4통 → 1~2통.

## 열린 질문과 위험 요소
- 기존 하자 전산이 현장에서 왜 안 쓰이게 됐는지 아직 모른다. 같은 이유로 실패할 수 있으니 시스템 담당 부서에 확인할 예정이다.
- 정보보안 심의 절차와 기간을 모른다. 시범 일정에 가장 큰 변수다.
- 시안이 설득에 성공하려면 "과장이 1분 안에 등록하는 장면"과 "본부 화면에 12곳이 한 번에 모인 장면" 두 가지가 시연돼야 한다.
